# Ubuntu live dictation design

Approved product behavior: user confirmed "den erkannten text waehrend er Aufname bearbeiten. neuer text wird einfach angehaengt". Continue native implementation under existing authorization; no repeated scope-approval loop.

Recording in local mode automatically transcribes approximately five-second PCM sections while full audio is recorded to its existing private WAV. New results append at the buffer end using Gtk.TextBuffer.insert, never replacing the buffer or rewriting user corrections. The editor is editable during capture, draining, and after completion. Changes checkpoint to the existing history row without deleting audio or changing its recording status. Stop finalizes WAV, flushes the tail, drains ordered inference, and saves the current edited buffer before audio cleanup. Silence is a valid empty live section; malformed responses remain errors.

Approaches: repeated transcription of the entire growing file wastes increasing CPU and risks replacing edits. A new streaming ASR stack adds dependencies and model changes. Choose bounded sections through the existing local CPU service: small fixed request cost and append-only results. Section boundaries can reduce recognition quality; genuine token streaming, overlap reconciliation, long meetings and cloud-live inference are outside this slice.

Keep GTK main-thread-only; GStreamer only copies raw S16LE 16 kHz mono PCM into a bounded session. One sequential worker writes private temporary complete WAV chunks and reuses TranscriptionJob deadlines/cancellation. At most five minutes of queued audio (9.6 MB PCM) and one inference request; slow inference drains after Stop with a visible pending status. Reject overflow explicitly; retain full recording. Session identity guards discard stale callbacks. Live failure never silently replaces partial edited text with a full re-transcription. Full-audio retry with existing edits must require explicit replacement confirmation or be blocked with a clear instruction.

The checkbox "Live transcription (local CPU)" defaults on for local mode and is disabled for cloud mode. Disabling it preserves manual batch recording. Existing GTK recording and close/quit guards remain. Cancel invalidates live callbacks and retains draft/audio; unfinished WAV may be invalid. New/open/delete/quit flush edits and refuse losing unsaved text. Debounced edits use small existing SQLite operations; export continues off GTK. Schema v1 can store drafts in the existing transcript column; do not mark a draft completed. Explicitly editing a completed history result updates text without re-transcribing.

Test without real microphones/private history: deterministic ordered chunks, tail/silence/errors/cancel/deadline/overflow; actual headless lifecycle and storage tests; GStreamer audiotestsrc to local container for real live append and edits; GTK EN/DE isolated roots. Never kill a running recording. No automatic cloud fallback, new model, credential changes, or unrelated Docker restart-policy changes.
